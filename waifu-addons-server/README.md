# Waifu Addons — сервер и сайт

Основной каталог владельца: http://132.243.115.51:4853. Собственный экземпляр запускается через Docker: см. README-DOCKER.md.

Сайт и API используют один каталог. Посетителям доступны поиск, страницы аддонов, история версий и скачивание `.waifu`. Кнопка «Опубликовать» принимает готовый пакет или папку с `waifu-addon.json`. Публикация требует ключ издателя; id аддона закрепляется за первым издателем. Каждая следующая версия должна быть выше предыдущей. Опубликованные версии не перезаписываются.

## Твой ключ публикации

Запусти `Open-Publisher-Key.cmd`, скопируй ключ в поле «Ключ издателя» на сайте. Он сохранён только локально в `.private/data/waifu-token.txt`, не включён в исходный репозиторий и не встроен в сайт. Ключ разрешает публикацию от издателя `waifu`. Не отправляй его вместе с аддоном.

## Локальный запуск

Нужен Node.js 22 или новее. Зависимости устанавливать не требуется.

- Запусти `Start-Server.cmd` или `node server.mjs`.
- Локальный адрес: http://127.0.0.1:4317.
- Данные и ключи находятся в `.private/data`; этот каталог исключён из Git.
- Переменные окружения: `HOST`, `PORT`, `WAIFU_DATA_DIR`.

У локального и размещённого серверов отдельные хранилища. Начальный ключ издателя один и тот же; новые локальные публикации автоматически в облако не переносятся. Для публикации в облако используй публичный сайт.

## Издатели

`node cli.mjs publisher author-id` создаёт отдельный ключ и сохраняет его в `.private/data/author-id-token.txt`. Локальный сервер подхватывает его автоматически. Для размещённого сайта администратор должен дополнительно обновить серверный secret `WAIFU_PUBLISHERS_JSON`, добавив SHA-256 ключа с соответствующим id, и применить новую конфигурацию публикацией версии сайта. На первом этапе регистрация авторов работает по приглашению, без публичного создания аккаунтов.

## Пакеты

`node cli.mjs pack <папка-аддона> <имя.waifu>` создаёт пакет. Форма сайта умеет делать то же из выбранной папки. Примеры находятся в `examples/hello` и `examples/uppercase`.

Формат `.waifu` — JSON-конверт `waifu-addon-v1` со списком файлов в Base64. Корневой `waifu-addon.json` содержит `id`, `name`, `version` (три числа), `apiVersion: 1`, `main` (относительный путь к `.cjs`), `commands`, необязательные `description` и `permissions`. Сервер назначает `publisher` по ключу, а не доверяет этому полю в загрузке.

Ограничения первой версии: пакет до 12 МБ, до 200 файлов, один файл до 2 МБ, общий размер файлов до 8 МБ, до 100 версий на аддон. Скрытые файлы, .git и node_modules не публикуются; внешние зависимости нужно объединить в .cjs. Ссылки, пути с выходом из папки, Windows-алиасы и дублирующиеся пути не поддерживаются. Код загруженных аддонов на сервере не исполняется. Проверка структуры и SHA-256 не являются антивирусной проверкой или цифровой подписью автора.

## Waifu Code

Waifu Addons 0.3 подключает сетевой каталог. Настройка `waifuAddons.registryUrl` задаёт адрес сервера на уровне приложения. Установка из каталога проверяет SHA-256 и запрашивает доверие к коду. Команда `Waifu Addons: Install Package` устанавливает скачанный .waifu; `Waifu Addons: Publish Addon` открывает форму сайта. Для применения обновления перезапусти редактор.

## API

- GET `/api/health` — работоспособность API.
- GET `/api/addons` — страница каталога; `nextCursor` передаётся в `?cursor=` для следующей.
- GET `/api/addons/{id}` — описание и версии.
- GET `/api/addons/{id}/{version}/package` — скачивание с неизменяемым SHA-256.
- POST `/api/addons` — публикация JSON-пакета, заголовок `Authorization: Bearer <ключ>`.

## Хранение и сборка сайта

Локально используются файлы с атомарной записью. Размещённый Worker использует R2, а конкурентные публикации защищены условной записью по ETag. `WAIFU_PUBLISHERS_JSON` хранится как secret Sites. Исходные ключи и локальные записи не входят в Worker-артефакт. Точки хранения и авторизация общие для страниц сайта и API.

`node scripts/build.mjs` собирает автономный Worker в `dist/server/index.js`; `node scripts/validate-artifact.mjs` проверяет ESM-артефакт. `node --test test/*.test.mjs` запускает серверные тесты. Браузерная проверка в исходном общем workspace: `node test/browser-check.mjs` (использует Playwright из соседнего проекта Waifu Code и установленный Chrome).

Перед самостоятельным публичным развёртыванием настрой HTTPS, ограничения нагрузки и резервное копирование хранилища. Для локального режима сервер по умолчанию доступен только с этого компьютера.
